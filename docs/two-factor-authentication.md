# Two-Factor Authentication

This package supports multiple two-factor authentication (2FA) methods to protect user accounts.

## Supported Methods

- **TOTP** - Time-based one-time passwords generated by authenticator apps (Google Authenticator, Authy, etc.)
- **Email** - Verification codes sent via email
- **Phone** - Verification codes sent via SMS

## Enabling 2FA

### TOTP Setup

1. **Initiate setup** - `POST /api/2fa/setup` (requires authentication)
   - Returns a secret and QR code URL
   - The 2FA is not enabled until confirmed

2. **Confirm setup** - `POST /api/2fa/confirm` (requires authentication)
   - Submit a valid TOTP code from the authenticator app
   - On success, 2FA is enabled and recovery codes are returned

### Email/Phone Setup

Email and phone 2FA are configured through the package events. When enabled, the package dispatches `VerificationCodeGeneratedEvent` with the verification code and optional magic link. Your application must listen to this event to send the code via email or SMS.

## Logging In With 2FA

When 2FA is enabled, the standard login flow changes:

1. **Initial login** - `POST /api/login`
   - User submits email/phone/username and password
   - The API returns `two_factor_required: true` with the method and a pending token

2. **Verify the 2FA challenge** - `POST /api/2fa/verify`
   - For TOTP: submit the code from the authenticator app
   - For email/phone: submit the verification code
   - For recovery codes (TOTP only): submit a recovery code longer than 6 characters

### Magic Links

For email/phone-based 2FA, a magic link is included in the `VerificationCodeGeneratedEvent`. Users can click the magic link to complete authentication without entering a code.

Magic links can also authenticate users who have TOTP enabled, providing a fallback when the authenticator device is unavailable. When a valid magic link is used, the user is logged in without requiring a TOTP code.

## Recovery Codes

Recovery codes are generated when TOTP 2FA is confirmed. These single-use codes allow users to authenticate or disable 2FA if they lose access to their authenticator device.

- Store recovery codes securely
- Each code is removed from the account after use
- Recovery codes are encrypted at rest

## Disabling 2FA

`POST /api/2fa/disable` (requires authentication)

### TOTP Disable

Requires one of the following:
- A valid TOTP code from the authenticator app
- A valid recovery code (codes longer than 6 characters)

If all recovery codes have been used, 2FA can be disabled with just the bearer token to prevent permanent account lockout.

### Email/Phone Disable

This is a two-step flow:

1. **First call** - Sends a verification code and returns a pending token
2. **Second call** - Submit the pending token and verification code to disable 2FA

## Security Notes

- 2FA secrets and recovery codes are encrypted at rest
- Magic links are single-use, time-limited, and stored as hashed tokens
- Rate limiting is applied to 2FA verification and resend endpoints
- The backend never trusts frontend flags for 2FA status
